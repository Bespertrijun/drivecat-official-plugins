# OneStrm 自动工具

监控上传到选中的 115 网盘成功后，通知 OneStrm 扫描文件所在的云端目录。STRM 由 OneStrm 自身规则生成。

## 配置

1. 选择 DriveCat 中一个已启用的 115 网盘。该网盘的所有监控规则都可触发通知。
2. 填写 DriveCat 能访问的 OneStrm 服务地址和 Token；默认使用 Bearer 鉴权，也支持 query token。
3. 确认 OneStrm 使用同一个 115 账号，开启自动通知并保存。

Token 留空保留原值；需要删除时勾选“清除已保存的 Token”。测试连接只做 TCP 连接检查，不验证鉴权或扫描接口。“提交测试扫描”使用已保存设置，实际提交填写的云端目录。

不需要额外路径映射。例如监控 `/下载`，远程目标选 `/影视`，文件 `/下载/某剧/01.mkv` 上传后的完整云端路径是 `/影视/某剧/01.mkv`，扫描目录就是 `/影视/某剧`。根目录文件的父目录 `/` 也是合法结果；路径缺失会标记待核查，不回退到根目录。

第一版接入监控上传及恢复成功的 `after_upload`，不接入跨盘转存和同步事件。首次开启只处理启用后完成的上传；同一任务可以在启用前创建。

## 接口约定

沿用用户提供的 demo：

```http
POST <OneStrm 服务地址>/webhook/quick_scan
Authorization: Bearer <Token>
Content-Type: application/json

{"paths":["/影视/某剧"]}
```

每个请求发送一个目录；query 模式通过 `?token=...` 传递 Token。请求不携带 115 Cookie，不跟随重定向，不继承环境代理。

**按用户确认，所有 HTTP 2xx 都记为“通知成功”，不解析响应体判断业务成功。** 这只表示 HTTP 请求被接收，不表示已经扫描完成或生成 STRM。接口、鉴权和重复扫描在实际 OneStrm 版本上的行为仍需实机验证；本插件不提供 STRM 完成回调。

## 队列与失败处理

- 同目录默认安静 10 秒后发送，每批最多合并等待 60 秒；后台每 2 秒检查一次，实际发送还受调度及服务可用性影响。
- 一次只发送一个请求。发送期间新增文件进入下一批；同一目录成功后又上传文件会再次通知。
- 网络失败、超时及 5xx：初次请求后最多重试 3 次，间隔为 30 秒、2 分钟、10 分钟。429 同时遵守有效 `Retry-After`，暂停该服务目标的发送。
- 401/403 暂停该目标的自动发送；修改 Token 或鉴权方式并保存后恢复。其他不可重试错误、重试耗尽保留记录，可手动重试或取消。
- 通知失败不会修改上传成功状态，也不会让文件重新上传。
- 允许偶发重复通知，不保留逐文件永久防重记录。取消仅针对当前批次；后续重复事件、补查或新上传可以再形成请求。
- 关闭自动通知暂停已有队列，重新启用同一目标可继续；关闭期间完成的新任务不自动回补。普通重启保留启用时段并继续补查。
- 更换网盘或 OneStrm 地址后，旧队列显示“配置已变更”，不会转发到新目标。切回原目标可继续处理。

每 60 秒只读补查宿主成功上传记录，按完成时间和任务 ID 分页（每页 500 条，每次调度最多两页）。完成时间水位、分页进度与入队事务一起保存，重叠 2 分钟并预留 5 秒提交缓冲。先创建但晚完成的任务不会因为 ID 较小而被跳过。清理历史不重置补查进度。

补查依赖宿主仍保留的成功记录；无法恢复宿主已删除的历史。超出重叠窗口的延迟提交、回填旧时间、系统时钟大幅回拨不能保证补查完整。重叠查询和网络超时恢复都可能重复通知。

## 持久化与清理

复用宿主 `context.get_fs().root` 提供的专属目录，默认是：

```text
DriveCat 数据目录/plugin_data/<宿主分配的插件ID>/
  config.json    # 原子写入设置，包含本地 Token
  state.sqlite3  # 待处理任务、重试、补查进度、通知历史
```

本地安装的目录名为 `onestrm`；市场安装的 ID 由宿主派生，代码不硬编码数据路径。目录权限为 0700，配置和数据库为 0600，Token 不回显、不进入队列或日志；Token 是本地明文保存，并未加密。

通知成功后删除该批待处理条目和逐文件明细。成功及取消的历史摘要保留 30 天，最多 10,000 条，每日清理，也可手动清理。未完成、失败及待核查记录继续保留。SQLite 删除后会复用空闲空间，文件不一定立即变小；空闲维护时按需整理。积压队列不受历史数量上限限制。

Docker 需要持久化挂载包含插件数据的目录；仅重建容器而未保留该目录会丢失设置和队列。

## 开发验收

复用现有宿主钩子、网盘摘要、只读数据库和 APScheduler API，界面使用共享 `sdk.js` 和宿主主题。SQLite 使用 Python 标准库，HTTP 使用宿主已有 aiohttp；不新增第三方依赖。`drive.upload` 权限用于注册 `after_upload`，插件不执行上传；宿主数据库只有 `db.read` 权限。

在仓库根目录执行（`python` 指宿主 Python 环境）：

```sh
python -m unittest discover -s tests -p 'test_onestrm.py' -v
DRIVECAT_BACKEND=/path/to/DriveCat/backend python tests/onestrm_host_check.py -v
CHROME_BIN=/path/to/chrome node tests/onestrm_ui_smoke.cjs
python -m ruff check plugins/onestrm tests/test_onestrm.py tests/onestrm_host_check.py
node --check plugins/onestrm/ui/app.js
```

宿主集成测试在临时数据库中运行真实进程沙箱、只读 ORM、持久化调度器及本地 HTTP 假服务；打包测试在临时 Git 仓库里调用现有打包函数。浏览器测试使用已安装 Chromium 和 Node 内置 CDP WebSocket，不安装依赖。DevRT 的调度器是占位实现，不能用其页面测试替代宿主集成验收。

具体结果与待验收项见 [验收记录](ACCEPTANCE.md)。发布仍沿用仓库的 Git tag 打包流程，开发验收不会发布市场版本。
