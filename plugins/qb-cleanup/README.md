# qBittorrent 后处理清理

选择需要联动的 Watcher。插件按完整文件路径关联上传任务与 qB 种子，在**至少一条关联任务、所有关联任务及有效上传目标成功、qB 下载完成、安静期通过**后移除种子任务。请求固定为 `deleteFiles=false`，下载数据仍由 DriveCat 自己的后处理管理。

无需修改 DriveCat 主仓，不依赖新增 hook。使用已有 `db.read`、插件数据目录和定时任务接口；不写宿主业务表，不新增第三方依赖。

## 配置

1. 填写 DriveCat 能访问的 qB WebUI 地址、用户名、密码，测试连接。Docker 中 `localhost` 指向 DriveCat 容器自身，应使用 qB 服务名或可达主机地址。
2. 选择 Watcher。只有启用且上传后处理为“删除”的规则参与处理；其他规则会显示但不参与。
3. 填写路径映射，例如 DriveCat `/downloads` → qB `/data`。两端必须指向同一份数据；相同路径也显式配置。支持多条 Linux/Docker 绝对路径，最长目录前缀优先，不支持 `..`、Windows 路径或按文件名猜测。
4. 设置检查间隔（默认 10 秒，5–300 秒）及安静期（默认 60 秒，1–86400 秒），启用并保存。
5. “检查已保存映射”读取最多 40 个种子和 100 条任务样本，仅诊断，不删种。“立即检查 / 重试”执行正常判断，不绕过安静期；未启用时不删种。

密码查询不回传明文。页面密码留空保留原值；API `password: null` 或省略同样保留，显式空字符串清除。试验 hook 版本的旧配置会以禁用状态加载，选择 Watcher 后再启用。

## 多文件与边界

- 一个文件可关联多个辅种，每个种子独立判断。同名不同路径不会匹配。
- 不要求 Watcher 任务数等于 qB 文件数。字幕、NFO 等没有关联任务的文件仍存在，不阻止清理。
- pending、running、failed、retry、cancelled、未知状态及缺失上传目标都不是成功。不同任务 ID 即使已成功，也会重置安静期。
- 文件版本使用 Watcher、路径、大小、mtime、上传目标识别。旧失败记录和新成功记录无法证明替代关系、多版本、大小不符、映射歧义或已观察历史消失时保留并提示。
- 种子代际绑定 qB 地址、hash、added_on、保存路径。任务创建时间早于当前种子添加时间不能授权清理；历史导入时间不可靠时需要人工检查。
- qB 仍在下载、移动或校验时不开始等待。种子清单、配置或有效目标变化都会重新观察。
- 安静期基于本次运行的单调时钟；重启、停用、断连、查询失败和观察中断后重新等待。最终删除前重新读取任务、目标、配置、qB 状态和清单。
- 上传成功不等于后处理已删文件。插件不读取本地文件是否存在，也不处理排除规则直接删除文件的事件。

**宿主没有“这个种子的所有文件都已发现”的信号。** 安静期只能缓冲新任务，不能证明扫描完成；任务可能在安静期之后才出现。最终查询与 qB 删除之间也存在跨系统竞态。固定保留下载数据，但移除种子意味着不再由该种子任务下载/做种。

## 重试与持久化

数据在宿主 `data/plugin_data/{plugin_id}/`（可由宿主配置）下：

- `config.json`：连接及规则配置，权限 0600，原子替换。
- `state.sqlite3`：磁盘上的 SQLite 数据库，保存当前候选/任务快照、扫描游标、实例级重试和结果。不需要独立数据库服务。

连接拒绝、超时、HTTP 5xx/429 等按 30 秒、1 分钟、5 分钟、15 分钟退避，之后保持 15 分钟并带少量抖动；退避跨重启保留。会话失效立即重新登录一次，错误密码、持续认证拒绝、证书和 HTTP 地址错误暂停自动登录，修正配置或手动重试后恢复。DNS/连接失败按暂时错误重试，因为仅凭断连无法判断地址是否永久错误。

删种前先持久化删除意图。响应丢失或进程退出后查询原代际是否仍存在；已不存在则完成，仍存在则重新判断并等待完整安静期。状态存储不可写或损坏时停止删除，不自动抹掉数据库继续运行。

当前快照覆盖更新，不每轮追加。完成后移除任务明细，摘要保留 30 天且最多 10,000 条，每天清理；可手动清理完成历史。活跃/重试记录不静默丢弃，取消标记保留以防同一代际再次被发现。移出所选范围的快照保留 7 天。SQLite 默认回滚日志、短事务、独立连接；大于 32 MB 且超过一半空闲页时在清理后压缩。

宿主没有插件容量配额。页面显示数据库大小及各状态数量。卸载后独立数据目录由宿主管理，不能假设自动删除。

## 调度与规模

复用宿主调度器，模块级回调每 5 秒唤醒，按已配置间隔检查。后台线程执行数据库和网络操作，串行锁防止自动/手动处理重叠。所选 Watcher 历史按 ID 每页 500 条完整重查，避免漏掉旧任务晚成功；单轮仍需在内存中汇总所选历史。每次最多检查 40 个种子，持久化轮转游标。种子很多时每个候选的观察周期随批次数增加，最终清理可能晚于安静期；观察间隔超过预期周期的三倍（至少 30 秒）会重置等待。

## 验证

```sh
python -m unittest discover -s tests -v
node --check plugins/qb-cleanup/ui/app.js
python tests/qb_host_integration.py /path/to/DriveCat/backend
python -m devrt.server plugins/qb-cleanup
```

DevRT 提供示例 Watcher/任务供页面调试，其调度为空实现；调度验证必须用独立宿主集成脚本。宿主集成仅用临时数据库，验证真实只读 DbProxy、分页、持久化调度和加载/卸载。发布包的版本号继续由仓库打包脚本注入。

API 依据：[qB 官方 WebUI API](https://github.com/qbittorrent/qBittorrent/wiki/WebUI-API-(qBittorrent-4.1))。本地验证使用模拟 qB，不代表真实 qB 或发布镜像验证。发布前仍需在目标镜像及专用 qB 测试实例验证。
